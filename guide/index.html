Guía de FireDex

Todo lo que necesitas para crear addons, modelos y animaciones de Minecraft Bedrock, y para entender cómo funciona FireDex por dentro.

Contenido

1. Inicio rápido · 2. Proyectos y datos · 3. Estructura de un addon · 4. Editor de código · 5. Modelador 3D · 6. Animaciones · 7. Integración con el addon · 8. Atajos · 9. Para desarrolladores · 10. Problemas y límites

1. Inicio rápido

Crear un addon: en Inicio pulsa Crear proyecto o sube un .mcaddon/.mcpack/.zip. Se abre el editor de código con el árbol de archivos.

Crear solo un modelo: pulsa Nuevo modelo 3D. No necesitas un addon: FireDex crea un proyecto independiente con models/entity, animations y textures/entity. Cuando quieras, lo integras en un addon (sección 7).

Todo se guarda en tu navegador (IndexedDB). No se sube nada a ningún servidor. Exporta con el botón Exportar (zip / .mcaddon) para hacer copias de seguridad.

2. Proyectos y datos

Cada proyecto es un árbol de carpetas y archivos guardado en la base devstudio_db: projects_index (lista con nombre y fecha) y projects_data ({id, name, root, meta}).

root: { id, type:"folder", kind?:"model", children:[ { id, type:"file", name, content } ... ] }

• Los archivos de texto guardan su contenido como texto; las imágenes como data URL.
• root.kind === "model" marca un proyecto de modelo independiente: se abre directamente en el modelador.
• meta guarda datos auxiliares del modelador (colores de cubos, identificador de entidad).
• El proyecto activo se recuerda en localStorage.devstudio_active_project.

Borrar los datos del navegador borra tus proyectos. Exporta con frecuencia.

3. Estructura de un addon

MiAddon/ ├─ behavior_pack/ │ ├─ manifest.json │ ├─ entities/ (*.json — comportamiento) │ ├─ items/ blocks/ recipes/ loot_tables/ │ ├─ functions/ (*.mcfunction) │ └─ scripts/ (Script API, *.js / *.ts) └─ resource_pack/ ├─ manifest.json ├─ models/entity/ (*.geo.json — geometrías) ├─ animations/ (*.animation.json) ├─ entity/ (*.entity.json — entidad cliente) ├─ textures/entity/ (*.png) └─ texts/en_US.lang pack_icon.png

• Usa un namespace propio: mi:espada, nunca minecraft:.
• Cada pack necesita UUID únicos (usa el generador de Manifest).
• La entidad de comportamiento (BP) define qué es y qué hace; la entidad cliente (RP) define cómo se ve: modelo, textura y animaciones.

4. Editor de código

Árbol de archivos: iconos por tipo (JS, TS, JSON, mcfunction, lang, imágenes…), crear, renombrar, duplicar, mover, borrar (con aviso para deshacer), subir archivos y carpetas completas, buscar por nombre.

Edición: resaltado de sintaxis propio, números de línea, autocierre de paréntesis y comillas, sangrado automático, comentar (Ctrl+/), mover líneas (Alt+↑/↓), buscar y reemplazar (Ctrl+F), formatear JSON, pestañas que se recuerdan.

Historial: deshacer/rehacer con agrupación de escritura, y flechas Atrás/Adelante para volver a la posición anterior del cursor. En el árbol, borrar o mover muestra un aviso con «Deshacer».

Sugerencias de Minecraft: al escribir en JavaScript o TypeScript aparece una lista con clases, métodos, propiedades, eventos (world.afterEvents.…), componentes y plantillas. Deduce el tipo por el nombre de la variable, anotaciones TS, const x = cadena… y for…of. Elegir una clase sin importar ofrece importar automáticamente desde @minecraft/server / @minecraft/server-ui. En archivos .mcfunction sugiere comandos.

Detección de errores: rojo = error que rompe (sintaxis, JSON inválido, manifest incorrecto); amarillo = posible problema (evento desconocido, variable sin usar, UUID repetido, versión rara); azul = sugerencia. Pulsa el subrayado para ver el motivo y el arreglo rápido. En TypeScript se revisa estructura y paréntesis, no los tipos.

Móvil: barra de teclas extra (Tab, llaves, flechas, deshacer), el teclado no tapa el cursor, lista de sugerencias sobre el teclado y panel de archivos deslizable.

Modelos: al abrir un .geo.json o .animation.json aparece el botón Modelo que lo abre en el modelador.

5. Modelador 3D

Editor de geometrías Bedrock (*.geo.json, formatos 1.12 y antiguo 1.8) con visor WebGL propio: no necesita internet ni librerías externas.

Modos (arriba)

Modelar (1) · Mapeo UV (2) · Pintar (3) · Animar (4).

Modelar

• Esquema: huesos (naranja) con sus cubos (con color propio), mostrar/ocultar y plegar.
• Herramientas: Elegir, Mover, Rotar y Tamaño con ejes sobre el modelo; añadir cubo/hueso, duplicar, borrar.
• Más herramientas: espejo en X, centrar pivote, agrupar en hueso, rotar cubo 90°, dividir cubo, alinear al suelo, centrar modelo, ajustar a enteros, escalar todo el modelo, mostrar/ocultar todo.
• Propiedades: origen, tamaño, pivote, rotación, inflate, espejo UV, color y hueso padre. Los huesos tienen nombre, padre, pivote y rotación.
• Teclado: flechas y RePág/AvPág mueven la selección según el Ajuste (1, 0.5, 0.25 o libre).
• Vista: perspectiva/ortogonal, malla, cuadrícula, sombreado y modo textura/color (menú ⋮).

Cómo funciona un modelo Bedrock

Un modelo es una lista de huesos; cada hueso tiene pivot, rotation, un parent opcional y cubes. Un cubo tiene origin (esquina mínima), size, uv, y opcionalmente pivot, rotation, inflate, mirror. Las unidades son píxeles (16 = 1 bloque). El hueso hijo hereda la transformación del padre.

{ "format_version": "1.12.0", "minecraft:geometry": [{ "description": { "identifier": "geometry.zombi", "texture_width": 64, "texture_height": 64 }, "bones": [ { "name": "body", "pivot": [0,12,0], "cubes": [ { "origin": [-4,12,-2], "size": [8,12,4], "uv": [16,16] } ] } ] }] }

UV y texturas

• UV de caja ("uv": [u, v]): la textura se despliega automáticamente desde (u, v) en forma de cruz (este, norte, oeste, sur, arriba, abajo).
• UV por caras ("uv": { "north": { "uv": [..], "uv_size": [..] } }): cada cara se coloca libremente.
• En Mapeo arrastra las caras sobre la textura: el modelo se actualiza en tiempo real. Auto UV reorganiza todo, Píxel redondea a enteros, Caras pasa un cubo a UV por caras.
• En Pintar usa lápiz, borrador, relleno y cuentagotas directamente sobre el modelo 3D o sobre el mapa. La textura se toma de un .png del proyecto (se busca por nombre) o puedes cargar/crear una.
• El tamaño de textura (texture_width/height) se cambia sin seleccionar nada.

Guardado, historial y borrador

• Los cambios NO se guardan solos en el proyecto. Pulsa Guardar (Ctrl+S); el botón se ilumina cuando hay cambios pendientes.
• Para que un error no te haga perder trabajo, FireDex guarda un borrador de seguridad aparte; si cierras sin guardar, al volver te pregunta si quieres recuperarlo.
• El botón Historial lista cada cambio con su nombre y hora: pulsa uno para volver (o avanzar) a ese punto. Deshacer/rehacer cubre geometría, colores, textura y animaciones.

Los colores de los cubos son solo visuales (se guardan en los datos del proyecto, no en el .geo.json, para no romper el archivo del juego).

6. Animaciones

El modo Animar edita archivos *.animation.json. FireDex busca el archivo automáticamente (por nombre o por contener animaciones del modelo). Si no lo encuentra, aparece «Sin archivo»: púlsalo para elegir uno, crear animations/nombre.animation.json o importar uno de tu equipo.

{ "format_version": "1.8.0", "animations": { "animation.zombi.walk": { "loop": true, "animation_length": 1, "bones": { "leftarm": { "rotation": { "0.0": [0,0,0], "0.5": [40,0,0], "1.0": [0,0,0] } } } } } }

Canales: posición, rotación y escala por hueso. Entre dos claves se interpola de forma lineal. Las claves con Molang se conservan pero se editan en el JSON.

Cómo animar: 1) crea o elige una animación (+) · 2) elige un hueso · 3) mueve el cursor de tiempo · 4) usa Mover / Rotar / Escala sobre el modelo, o escribe valores en el panel «Pose». Cada cambio crea o actualiza una clave en ese instante.

Línea de tiempo: arrastra la regla para recorrer el tiempo; arrastra un rombo para mover su clave; Supr borra la clave seleccionada; Ctrl+rueda hace zoom. Controles: reproducir/detener, duración, repetición (bucle, una vez, mantener al final), duplicar y renombrar.

Guardado: igual que el modelo, se guarda al pulsar Guardar. Los identificadores deben ser animation.<modelo>.<nombre>.

7. Integración con el addon

Pulsa el botón de enlace (🔗) del modelador. FireDex detecta y muestra: geometría, textura (ruta de recurso), archivo de animaciones y si existe una entidad cliente que use el modelo.

• Crear / actualizar entidad cliente: escribe entity/<nombre>.entity.json en el resource pack con la geometría, la textura y todas las animaciones (y reproduce idle automáticamente si existe). Si ya hay una con ese identificador, solo la actualiza.
• Crear entidad (Behavior Pack): genera entities/<nombre>.json mínima en tu BP.
• Copiar a otro proyecto: pone modelo, textura, animaciones y entidad en el resource pack del addon que elijas.
• Exportar .mcpack: resource pack listo para importar en Minecraft.

Dónde van las animaciones: en el resource pack, animations/*.animation.json. Si FireDex no las encuentra, defínelas con «Definir» en la ventana de integración o desde la línea de tiempo.

Ejecutar una animación en el juego

/summon fd:zombi /playanimation @e[type=fd:zombi] animation.zombi.walk import { world } from "@minecraft/server"; for (const e of world.getDimension("overworld").getEntities({ type: "fd:zombi" })) { e.playAnimation("animation.zombi.walk"); }

También puedes enlazarla en la entidad cliente: "animations": {"walk": "animation.zombi.walk"} y "scripts": {"animate": ["walk"]}. Activa los «Experimentos» de la versión si tu versión de Minecraft los requiere.

9. Para desarrolladores

FireDex es un sitio estático (HTML + CSS + JS sin framework). node build.js genera index.html, commands.html, guide.html y manifest.html; el editor (edit/index.html, ruta /edit/) y el modelador (model/index.html, ruta /model/) son páginas escritas a mano. Las rutas son limpias (/guide/, /terms/…): cada una es una carpeta con su index.html, así que el sitio debe servirse desde la raíz del dominio.

js/main.js menú principal, proyectos, wizard, creación de modelos js/co.js datos del editor: IndexedDB, árbol, modales, exportar js/co-ui.js Toolbox y utilidades de interfaz js/mcdata.js datos de la API de Minecraft (clases, eventos, componentes, snippets) js/editor-core.js tokenizador, linter, autocompletado, JSON/manifest (window.EC) js/editor-view.js motor del editor: textarea + resaltado, historial, búsqueda, móvil js/model.js modelador: WebGL, huesos/cubos, UV, pintura, historial, guardado js/model-anim.js animaciones: claves, línea de tiempo, pose js/model-int.js integración: entidad cliente, copiar, .mcpack css/*.css pixel.css (menú), editor.css, model.css

Editor

Un <textarea> transparente sobre un <pre> resaltado comparten un contenedor de scroll. El cursor y el menú de sugerencias se posicionan con métricas monoespaciadas. EC.tokenize/render colorea, EC.lint devuelve diagnósticos {from, to, sev, msg, fix} y EC.suggest las sugerencias. Para añadir clases o eventos de la API edita mcdata.js (TYPES, EVENTS, IMPORTS).

Modelador

El estado vive en S; el JSON del archivo (S.root) es la fuente de verdad. rebuild() recorre huesos y cubos, calcula matrices (boneMatrix) y genera las caras (faces) y el buffer WebGL. commit(etiqueta) guarda un paso de historial, reconstruye y marca cambios. Todo se expone en window.FD.

Ganchos (FD.hooks): snap y restore (historial), save (guardado y borrador), init, refresh. Así model-anim.js añade sus datos al historial sin tocar el núcleo. FD.pose(hueso) devuelve la pose animada de un hueso o null.

Añadir una herramienta: escribe una función que modifique S.root y termine con commit('Nombre'); añádela a la lista MORE en model.js.

Añadir un tipo de archivo al editor: registra la extensión en EC.LANGS (editor-core.js) y su icono en fileMeta (co.js).

Datos: los proyectos están en IndexedDB (sección 2). El guardado del modelador reescribe projects_data completo; no hay servidor.

10. Problemas y límites

• El visor no se ve: el navegador necesita WebGL (activa la aceleración por hardware).
• Perdí cambios: reabre el modelador; si hay borrador te lo ofrecerá. Los borradores se guardan en el navegador.
• Las rotaciones se ven distintas en el juego: el modelador aplica rotaciones directas en el sistema de coordenadas del archivo; verifica los modelos con rotaciones en Minecraft.
• Animaciones: solo interpolación lineal (no Catmull-Rom/bezier) y sin Molang editable; no hay animaciones de controladores.
• No incluido: selección múltiple, importar .bbmodel de Blockbench, modelos de Java, texturas animadas.
• TypeScript: se comprueba la estructura, no los tipos.
• Los proyectos viven en este navegador y este dispositivo: exporta para moverlos.
